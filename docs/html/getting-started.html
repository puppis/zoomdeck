Getting started

Get Zoomdeck as a desktop app or from the sources, open a deck, present it, export it to a folder or a single file, and set up your editor.

The overview showed what Zoomdeck does; this page gets it onto your computer and a deck of yours into it. There are two ways in: the desktop app, which needs nothing else, and the sources, which bring the zoomdeck command and the live development page.

The desktop app#

Download the build for your system from the releases: a .dmg for macOS, an .AppImage or .deb for Linux, an installer or a portable .exe for Windows. The app is the player and the preview server in a window of its own: open a deck.json, a Markdown file or a PDF from the File menu, by dropping it on the app, or by double-clicking it, and present as in the browser. The builds are not signed by a registered developer, so each system warns once the first time; The desktop app says what to click, and what the app's menus offer.

From the sources#

You need Node.js 20.19 or newer (or 22.12 or newer; odd-numbered releases such as 21.x fail inside the build with crypto.hash is not a function) and a browser with WebGL 2. Nothing else: no Python, no LaTeX, no video tools; formulas render through MathJax and the fonts are bundled.

git clone https://github.com/puppis/zoomdeck.git Zoomdeck
cd Zoomdeck
npm install        # dependencies, and this documentation into docs/html/
npm run dev        # the development page, with the tour deck
npm link           # optional: the `zoomdeck` command, from any folder

npm run dev serves http://localhost:5173/, which opens the tour deck; ?deck= selects another: /?deck=path/to/deck.json, /?deck=path/to/slides.md, /?deck=path/to/paper.pdf, or /?deck=examples/tree-deck&scene=Demo for a code-authored deck. The page reloads when a deck file changes and comes back to the stop you were looking at.

npm link puts a zoomdeck command on your path that runs the checkout as it is (so git pull updates it; npm unlink -g zoomdeck removes it). Without it, node bin/zoomdeck.mjs from the checkout does the same. If a shell or an editor answers command not found, npm's global bin folder (npm prefix -g prints its parent) is not on that program's PATH; the editor setups below find the command on their own, and Editors covers the rest.

Open a deck#

zoomdeck serve talk/deck.json      # also talk/slides.md, or paper.pdf
zoomdeck serve talk/deck.json --host   # reachable on the network, for a tablet

The preview opens the deck in your browser at http://127.0.0.1:8000/ (or the next free port, printed in the terminal), reloads it on every save and keeps your position. The argument is a deck.json, a Markdown file (a deck.json next to it that names it is used), a PDF, or a JS/TS module exporting a deck. Ctrl+C stops the server; it also stops by itself when the program that started it, an editor's build panel say, ends.

Present it#

The preview, the exports and the app all play a deck with the same player, so what you try here is what the audience sees. → or Space advances and ← goes back; O opens the outline, F the fullscreen view and , the settings, where every key and gesture can be changed. Hold Shift for the spotlight (L makes it a laser), press D to draw and W for the whiteboard, C for the camera, R to record a talk and P to print the deck. The player describes each tool, and chapters 4 to 6 of the tour show them live.

Export it#

zoomdeck build talk/deck.json -o out/talk             # a folder: index.html, assets/, deck/
zoomdeck build talk/deck.json -o out/talk --one-file  # one HTML file, every asset inside

The folder is hosted or copied as a whole; the single file opens by double-click and needs no server. Both run the deck's program when they load, so a changed deck needs a new export. The player's Print button writes a PDF with a page per stage or per slide. Exporting a deck has the options.

Write a first deck#

A deck is a Markdown file, and nothing more is needed to start; deck.json next to it holds the title and other settings when you want them.

::: slide {#start width=20}
# My first deck

Slides are `::: slide` containers; this one has a 20 × 11.25 canvas.

[[include: #details x=4 y=-2 width=9 preview=true]]
:::

::: slide {#details}
## Details

[Shown on the first click]{#a step=1}

[And on the second]{#b step=2}
:::
{
  "markup": "slides.md",
  "title": "First deck"
}

Every slide has an #id; the slides nothing includes are visited first to last; width on a slide sets its canvas, and x, y, width on an include place a child inside its parent. The notebook Your first deck, stage by stage builds such a deck one cell at a time, with the result under each cell, and lets you edit it in the browser. A deck folder grows from there:

talk/
├── slides.md        the slides, in the Markdown dialect
├── deck.json        title, colors, typography, presenter options, styles, macros
├── assets/          images, videos, pages referenced from slides.md
├── parts/           optional: Markdown files spliced in with [[import: path.md]]
├── code-slides.ts   optional: Slide classes used by [[subslide: Name]]
└── recordings/      talks recorded by the player, when the deck is served

Paths in slides.md resolve relative to the Markdown file.

Set up your editor#

Editing is most comfortable when the browser follows your typing. The editors/ folder of the repository has ready-made setups for VS Code, Sublime Text, Emacs, Vim/Neovim and JetBrains IDEs: they save after a second of idle typing, bind the preview, the jump from a source line to its stop and the single-file export to shortcuts, let the player open a stop's source line in the editor (E, or Alt + click on an element), and highlight the dialect inside Markdown. Editors explains each one.
