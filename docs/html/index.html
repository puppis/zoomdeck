Zoomdeck

Zooming presentations written in Markdown and played entirely in the browser.

What Zoomdeck does#

A Zoomdeck presentation is a tree of slides. Each slide has its own logical canvas and a small animation program; child slides sit inside their parent's canvas as viewports. Presenting means visiting the tree in pre-order: the camera zooms into each child, plays its steps and zooms back out (or cuts, when you prefer), so the audience always sees where a detail belongs.

You write slides in a Markdown dialect: prose, LaTeX formulas, images, video, shapes, diagram icons and arrows (crisp or hand-drawn), boxes and blobs around groups of elements, tables, charts, code listings, live web pages, fragments that appear on clicks, and animations such as moves, morphs and effects. When the dialect is not enough, a slide can be a small TypeScript class with the full animation engine at hand. Everything runs live on a WebGL canvas in the browser: a deck loads, records itself once, and then plays forwards and backwards instantly, with an outline, deep links, a pressure-sensitive pen, a highlighter, a whiteboard, a companion tablet, a camera view, a spotlight or laser, links on any element and configurable keys and gestures, and it records a talk (voice, camera and every move on the deck) that plays back on the deck itself or exports as a video, and prints every stage to a PDF. The same deck previews while you edit it and exports to a static folder or to a single HTML file that plays from disk.

See it: the guide deck is itself a Zoomdeck presentation, a tour of every feature with the markup that produces it next to the result. Source: github.com/puppis/zoomdeck.

  3. Concepts: what a slide, a viewport and a stop are, and how a deck is recorded and replayed.
  4. The player: presenting a deck: keys, the pen and the spotlight, the whiteboard and a companion tablet, the camera, recording a talk and printing the deck to a PDF.

The guide deck#

The guide is Zoomdeck's own demonstration and the companion of these pages: a presentation in which every chapter shows a feature next to the listing that produces it, organized in the same sections as this documentation. Open the guide: its front page lists the sections and jumps to any of them on a double-click, and each chapter links back to its page here.

The guide is a single self-contained HTML file next to these pages, exported from examples/guide/ when you run npm install (and again by npm run docs); it runs from disk or from any web server, and npm run dev opens the same deck live. Its sources (slides.md, deck.json, code-slides.ts and a few assets) are a good starting point for a deck of your own.

Documentation map#

Getting started

Install, write a first deck, set up your editor, and learn how a deck is played.

  • Getting startedInstall the project, get the zoomdeck command, write a first deck, preview and export it, and set up your editor.
  • EditorsEdit a deck and see it in the browser as you type, jump between a source line and its stop in both directions, or export the deck with a shortcut; ready-made setups for VS Code, Sublime Text, Emacs, Vim/Neovim and JetBrains IDEs, with syntax highlighting.
  • ConceptsSlides, logical coordinates, the zooming camera, and how a deck is recorded and replayed.

Presenting

The player and its tools: keys, spotlight and laser, the pen and the whiteboard, the camera, recording a talk, printing the deck, exporting it to a folder or a single file, and the desktop app.

  • The player guide ↗Keyboard and pointer controls, the pen and its pressure styles, the whiteboard, a companion tablet, the camera, recording a talk and exporting it as a video, printing the deck to a PDF, spotlight and laser, reverse playback, deep links, speed and fullscreen.
  • Exporting a deck guide ↗Turn a deck into a static folder or into one self-contained HTML file that plays anywhere, without Node or a server, or print it to a PDF.
  • The desktop appZoomdeck as a program of its own for macOS, Linux and Windows: the same player and preview server in a window, with menus, native dialogs and the command's flags.

Writing slides

The tree of slides and the content of a slide: prose, formulas, images, listings, tables and charts.

  • Slides and the tree guide ↗Slide containers, canvas sizes, includes, visit order, start and preview flags, placeholders.
  • Text guide ↗Paragraphs, headings, emphasis, colors, code spans, line breaks, lists and links.
  • Mathematics guide ↗Inline and display formulas, containers for formula attributes, macros and colored LaTeX.
  • Images and video guide ↗SVG and raster images, animated PNG and GIF, and video files played through the browser.
  • Code listings guide ↗Fenced code blocks as verbatim listings with syntax colors for common languages and for the slide dialect itself.
  • Tables and charts guide ↗Pipe tables with styled cells, rules and shading, and bar, line and pie charts drawn from rows of numbers, crisp or hand-drawn.

Diagrams

Shapes, arrows, icons and enclosures, crisp or hand-drawn.

  • Shapes, connections and attachments guide ↗Rectangles, circles, dots, ellipses, polygons, arcs and polylines; arrows and lines; braces, boxes and blobs.
  • Icons guide ↗Thirty-nine diagram symbols built from geometry (people, machines, files, marks and actions) with configurable outline, fill and label, crisp or hand-drawn.
  • Boxes and blobs guide ↗Surround a set of elements with a rectangle or with a smooth curve that keeps a chosen distance from every member, crisp or hand-drawn.
  • Hand-drawn shapes guide ↗sketch=true renders shapes, icons, arrows, lines, braces, boxes and blobs as if drawn by hand, with hatched or solid fills, through Rough.js.

Layout and style

Where things go and how they look: flow, anchors, constraints, groups, style sheets, and the deck.json configuration of a deck.

  • Positioning guide ↗Anchors, flow, explicit coordinates, relative constraints, at= expressions, offsets and sizes.
  • Groups guide ↗Several elements laid out in their own coordinates and handled as one element of the slide.
  • Styles guide ↗Named attribute sets applied by class tokens and automatically by roles such as heading, body or code.
  • Configuration guide ↗Every key of deck.json, the layout and presenter options, and the command line.

Motion and interaction

What happens on each click: fragments, animations, focus-only decorations and live web pages.

  • Fragments and steps guide ↗Reveal and hide elements on clicks, time the fades, advance automatically and skip events.
  • Animations guide ↗Move, rotate, scale, recolor and fade elements, play named effects, morph one element into another, follow paths, make geometry tremble, and move child viewports.
  • Focus-only decorations guide ↗Elements that appear only while their slide is focused, such as an opaque local canvas.
  • Live pages guide ↗Embedded web pages shown while their slide is focused, with a poster for previews.

Advanced

Slides written in TypeScript, a deck inside a page of your own, and the complete reference of the dialect.

  • Code-authored slides guide ↗Slides written in TypeScript with the complete animation engine, used alone or placed as subslides of Markdown decks.
  • A deck inside a pageMounting the player in an element of a larger page, the handle that drives it from the page's own script, and the features it can leave out.
  • ReferenceEvery container, element, directive and attribute of the dialect, grouped by topic, with the page that explains each.

The project#

Zoomdeck lives at github.com/puppis/zoomdeck; this site and the guide are published from it at puppis.github.io/zoomdeck. It needs Node.js 20.19 or newer (or 22.12 or newer) to install and build, and a browser with WebGL 2 to play decks; nothing else, no Python, LaTeX or video tools. Exported decks are plain HTML files.
