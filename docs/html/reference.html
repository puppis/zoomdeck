Reference

Every container, element, directive and attribute of the dialect, grouped by topic, with the page that explains each.

The dialect in one place, in the order of the documentation: the structure of a document, the content of a slide, diagrams, layout, motion, and the names that attributes accept. Each group links to the page with the explanations and examples.

Document structure#

Slides and the forest · Styles · Groups

Syntax Purpose
::: slide {#id attrs} … ::: a slide; attrs: title, width, height, start_here, only_this, return_to_parent, skip_return, transition, preview
[[include: #slide, placement, step, start_here, only_this, return_to_parent, skip_return, transition, preview]] a child slide placed in this one; subslide: #id is the same
[[subslide: ClassName, placement, step, …]] a code-authored child (Code-authored slides)
[[import: path.md]] splices a Markdown file in, between slides or inside one
::: styles … ::: style definitions, name: attributes per line, at the top of the file
::: {.element attrs} … ::: attributes for one paragraph, heading, image, formula, table or listing
::: {.group #id attrs} … ::: a group of elements in local coordinates
<!-- … --> discarded

Attributes are space- or comma-separated key=value pairs; quoted values may contain spaces and commas; (x,y) tuples stay whole; #id sets the ID; .name applies a style.

Names#

  • Colors: palette names (BLUE, TEAL, GREEN, YELLOW, GOLD, RED, MAROON, PURPLE, PINK, ORANGE, GRAY, WHITE, BLACK, with _A … _E variants), CSS names, #rgb, #rrggbb, rgb(…).
  • Effects: indicate, wiggle, circumscribe, flash, focus, grow, shrink, write, create, uncreate, draw, wave.
  • Rates: smooth, linear, rush_into, rush_from, there_and_back, ease_in, ease_out, ease_in_out.
  • Fill styles (hand-drawn shapes): hachure, solid, zigzag, cross-hatch, dots, dashed, zigzag-line.
  • Icons: user, users, client, desktop, phone, server, database, cloud, globe, document, folder, message, calendar, chart, check, cross, question, exclamation, info, warning, star, flag, pin, home, download, upload, search, arrival, departure, recycle, trash, key, lock, shield, bolt, gear, gears, puzzle, clock.
  • Style roles: heading, h1 … h6, body, math, code, image, iframe, group, include, shape and shape kinds, icon and icon-<name>, connection, arrow, line, attachment, brace, box, blob, table, chart.
  • Link targets: https://…, http://…, mailto:…, #slide=id, #step=N, absolute (/…) and relative (./…) paths.

Validation#

Mistakes are reported before anything is drawn, with the source line: unknown attributes, duplicate or missing IDs, conflicting constraints, positioning cycles, references across groups, inconsistent visibility, animations of hidden elements, invalid colors, unknown classes, effects and rates, unsupported link targets, and missing images.

Limitations#

  • Text is rasterized to canvas textures, redrawn at the screen's resolution whenever the camera comes to rest (so it may soften briefly during a zoom); math, SVG and shapes stay vector.
  • The dry recording happens at page load; large decks take a few seconds.
  • Group members cannot have their own fragments; transform works best between vector content.
  • Live pages are not drawn by the pen or spotlight and are absent from exported screenshots.
  • The design mode (dragging elements in the browser) is planned; see the roadmap in the repository.
